    How do you find images that look like a given image? We meet two landmark CNN architectures, Inception (GoogLeNet) and ResNet, use a pretrained ResNet-50 to turn images into embeddings, find similar images with nearest-neighbour search, measure its quality, and then speed it up with PCA and Annoy.

    01

    Image similarity and embeddings

    You are a data scientist at Pinterest. Given a query image, return the images in the catalogue that look most similar to it. Image similarity measures how alike two images are based on visual content: shapes, colours, textures and objects. Searching a collection for images similar to a query is often called reverse image search.

    What can you do with image similarity?

    Explore

    Unlabelled collections

    Explore large image collections by showing similar images: Google Images, Pinterest, “celebrity look-alike” websites.

    Cluster

    Online shop items

    Some categories, such as shoes, are visually distinct. Others overlap a lot with their neighbours.

    Clean

    Remove duplicates

    High-quality training data matters, and duplicates can hurt results. Similarity can find near-duplicates in a dataset.

    Lecture figures: Google, Pinterest, look-alike sites

    How do we measure how similar two images are?

    For vectors we can use the sum of squared differences, or related measures such as Euclidean or cosine distance. Applied directly to raw pixels these work poorly, because the meaning of an image lies in how pixels relate to each other, not in individual pixel values.

    Two common measures on vectors are Euclidean distance (straight-line distance) and cosine similarity (angle between vectors). For unit-length (L2-normalized) vectors they give the same ranking.

    What is an embedding?

    Computers work with numbers, so we convert each image into a vector that captures its content and scene. This vector is an embedding: images with similar content end up close together in the embedding space. So we first convert each image to a compact feature vector, then compare the vectors.

    Classical approach

    Hand-crafted features such as Gabor filters, SIFT, Local Binary Patterns or HOG, then compare those features.

    Deep learning approach (most common today)

    Use a CNN that maps an image to a vector.

    A Siamese network is one way to train such a mapping: two copies of the same CNN embed two images, and training pulls similar pairs together and pushes dissimilar pairs apart. We skip training and reuse a network already trained on a large dataset. Our ResNet-50 was trained for classification on ImageNet, not similarity, but its penultimate-layer features still work well as embeddings.

    Similarity vs classification

    Both use the same kind of CNN, but differently. A classifier only decides which category an image belongs to, so most of the information in the image is discarded in the final output. For similarity we take the representation just before the final classification layer, which keeps far more (shape, texture, layout) than a class label does.

    Feature extraction with a pretrained CNN: the convolutional layers already hold generally useful visual features. We retrain nothing; we run the images through the network and read the features out, using ResNet-50 and evaluating on Caltech-101.

  03
  
    Inception (GoogLeNet)
    
  
    AlexNet and VGG have two drawbacks: they are slow to train, and they are large on disk, mostly because of the big fully connected layers at the end. Can we get fewer parameters and better accuracy? Inception and ResNet do.
    
  
    GoogLeNet, built at Google, won the ImageNet (ILSVRC) classification challenge in 2014. It was introduced by Szegedy et al. in “Going Deeper with Convolutions” (paper). The name nods to the film Inception and “We need to go deeper”; making networks deeper was a main research goal at the time.
    
  
    Lecture figure
    
  
    Why is it important?
    
  
    1. It is small. GoogLeNet is much smaller than AlexNet and VGG even though it is deeper. Most weights sit in the dense layers, so the authors replaced the large fully connected layers with global average pooling and kept one small classifier on top.
    
  
    
  
    2. It introduced the Inception module. GoogLeNet is built from small blocks (micro-architectures) in which the data splits into several paths and is joined again. Inside one block, convolutions of several sizes run in parallel, so the block is a multi-scale feature extractor.
    

  
    Why a multi-scale feature extractor?
    
  
    It is hard to know which filter size a layer should use: 5×5? 3×3? 1×1, for purely local features? Instead of choosing, learn all of them: 1×1, 3×3 and 5×5 filters run in parallel and their feature maps are concatenated along the channel dimension. The next layer receives the combined result and does the same, so the network picks up both fine local detail and broader patterns at every stage.
    
  
    
  
    This image has three main elements: wheat, people and sky. An element covering a large part of the frame is best captured by a large kernel, a small element by a small kernel. An Inception module applies several kernel sizes at once, so each element is picked up at a suitable scale.
    
  
    

  
    The four branches
    
  
    
    
    1
    1×1 conv
    Local features at each position, and cheap channel reduction.
    
    
    2
    1×1 → 3×3 conv
    Medium-sized patterns.
    
    
    3
    1×1 → 5×5 conv
    Larger patterns and wider context.
    
    
    4
    3×3 max-pool → 1×1
    Some robustness to small shifts (the “pool projection”).
    
  
    
  
    
  
    A ReLU follows every convolution (left out of the diagram to save space). Branches 2 and 3 first apply a 1×1 convolution to cut the channels, then the 3×3 or 5×5; large kernels are expensive, so shrinking the input first saves computation, which is why the 1×1 layer usually has fewer filters than the larger convolution after it. Branch 4 uses 3×3 max pooling with stride 1; later work (Springenberg et al., “Striving for Simplicity”, 2014) showed pooling can be replaced by strided convolutions. Padding keeps every branch’s output the same height and width so the four outputs can be concatenated, and several Inception modules are stacked before a pooling layer reduces the spatial size.

    GoogLeNet is 22 layers deep counting only layers with parameters (27 with pooling layers).
    

  
    1×1 convolutions
    
  
    A 1×1 filter looks pointless: on a single-channel image it multiplies every pixel by a constant. On a multi-channel input it learns one weight per channel and sums the results, a learned linear combination of the channels at each pixel. This lets us change the number of channels cheaply (for example 192 to 16 before a 5×5 convolution) and add non-linearity through the ReLU that follows, at low cost.

  04
  
    Going deeper: ResNet
    
  
    A deeper network can represent more complex functions and learn features at several levels of abstraction, from edges in the early layers to complex object parts in the later ones. Networks have grown from a handful of layers (AlexNet) to well over a hundred.
    
  
    Does adding more layers always help?
    
  
    No. Very deep networks are hard to train. Backpropagation applies the chain rule, which multiplies one term per layer.
    
  
    
    
    Vanishing gradients
    If the terms are mostly smaller than 1, the product shrinks towards zero: early layers barely learn and training becomes extremely slow.
    
    
    Exploding gradients
    If they are mostly larger than 1, the product grows very large and training becomes unstable.
    
  
    
  
    Lecture figure: gradient norm of early layers
    
  
    The ResNet authors also reported a degradation problem: plain networks made deeper showed higher training error than shallower ones. Both problems motivate residual networks.
    

  
    ResNet and skip connections
    
  
    ResNet, from Microsoft Research, won ImageNet (ILSVRC) in 2015 (paper). Its key idea is the skip connection (residual connection), which makes very deep networks trainable: the ILSVRC entry used 152 layers, and the paper also trained a 1,202-layer network on CIFAR-10.
    
  
    
  
    y = F(x) + x
    
  
    F is a small stack of convolution layers and x is the block’s input, carried forward unchanged by the skip connection. The convolutions only have to learn the residual F(x) = y − x, which the authors argue is easier than the full mapping, especially when the best mapping is close to the identity.
    
  
    How do skip connections help with vanishing gradients?
    
  
      
    
    • The addition gives gradients a direct path back. Since d(F(x) + x)/dx = dF/dx + 1, the gradient reaching earlier layers does not vanish just because dF/dx is small.
      • 
    
    • The network behaves like a collection of paths of different lengths, many of them short, so it is effectively shallower.
      • 
    
    • If a block is not useful, it can learn F(x) close to zero and simply pass its input through.
      • 
  
    
  
    
  
    Code: the numeric check
    
  
    Plain network   : gradient factor = 1.0e-10
    With skip links : gradient factor = 2.59
    
  
    Lecture figure: loss surface with and without skip connections
    
  
    With skip connections the loss surface is much smoother and easier to optimise (Li et al., 2018).
    
  
    

  
    Building ResNet-50
    
  
    ResNet comes in versions named after their weighted layers: 18, 34, 50, 101 and 152. ResNet-50 uses bottleneck blocks: a 1×1 convolution that reduces channels, a 3×3 convolution, and a 1×1 convolution that expands channels again. There are two kinds of residual block.
    
  
    
    
    Identity block
    Used when input and output have the same shape, so x can be added directly.
    
    
    Convolution block
    Used when the shape changes (more channels, or a stride that shrinks the map). The skip path gets a 1×1 convolution so x can be added.
    
  
    
  
    
  
    Layer order of the main path: Conv, BatchNorm, ReLU, Conv, BatchNorm, ReLU, Conv, BatchNorm, add the input, ReLU.
    
  
    
  
    Code: IdentityBlock
    
  
    Code: ConvBlock and the shape test
    
  
    IdentityBlock: (1, 256, 56, 56)
    ConvBlock    : (1, 512, 28, 28)
    
  
    Why the ReLU between convolutions matters. Two linear operations stacked with nothing non-linear between them collapse into one linear operation, so every convolution in the main path is followed by (BatchNorm and) a ReLU, except the last, where the ReLU comes after the addition.
    

  
    The ResNet-50 architecture
    
  
    
  
      
    
    • A stem: 7×7 convolution (stride 2) and 3×3 max pooling.
      • 
    
    • Four stages with 3, 4, 6 and 3 bottleneck blocks. Each stage starts with a convolution block, followed by identity blocks.
      • 
    
    • Global average pooling turns the final feature map into a 2,048-dimensional vector. Without a classifier on top, this vector is exactly the embedding we want.
      • 
  
    
  
    Strictly, we put the stride on the first 1×1 convolution like the original paper; torchvision’s “v1.5” puts it on the 3×3 convolution. The parameter count is identical.

    ResNet-50 as a feature extractor
    
  
    Which pretrained model should we use? ResNet-50 is clearly more accurate than GoogLeNet (76.1% vs 69.8% top-1), although GoogLeNet is smaller. Compared with VGG, ResNet-50 has about five times fewer parameters and higher accuracy. Its 2,048-dimensional output is compact and widely used for retrieval. Training a deep CNN from scratch takes days and a lot of compute; with transfer learning we reuse ImageNet weights, here without any fine-tuning.

    Similarity search and its accuracy
    
  
    Given a query image, find the most similar images in the dataset with scikit-learn’s NearestNeighbors (brute-force algorithm, Euclidean distance). Because the vectors are L2-normalized, this ranks images exactly like cosine similarity. The query image is part of the dataset, so its nearest “neighbour” is itself at distance 0: asking for 5 neighbours gives the image plus 4 genuine neighbours.

    Measuring accuracy: precision@4
    
  
    Seeing a few examples is not enough. We use class labels as a proxy: for every image we take its 4 nearest neighbours (excluding itself) and count how many share its class. The score is the percentage of neighbours with the right class (precision@4). It is only a proxy: two images from different classes can still look alike.

  07
  
    Shrinking vectors with PCA
    
  
    There are two ways to speed up the search: reduce the length of the feature vectors, or use a better search algorithm. Less data means a faster search. ResNet-50 gives 2,048 features; at 32 bits (4 bytes) each, an image takes 8 KB, so a million images take about 8 GB. Different models give different feature lengths:
    
  
    ModelFeature length
    
    
    ResNet-18512
    ResNet-502,048
    VGG16 (output of the second fully connected layer)4,096
    Inception v32,048
    DenseNet-1211,024
    MobileNet v21,280
    EfficientNet-B01,280
    
  
    Most backbones give 1,000+ features. Cutting that to around 100 without hurting quality makes search far cheaper, and a small index fits in RAM instead of being loaded in parts.
    
  
    Reducing dimensions with PCA
    
  
    PCA re-expresses the features in new dimensions ordered by how much of the data’s variance they explain, so the first few components carry most of the information; each extra component adds less than the one before. We fit PCA once with 200 components; keeping the first d columns equals running PCA with d components. 150 components keep 87.6% of the variance.
    
  
    Code: fit PCA and plot variance kept
    
  
    Lecture figure: variance kept
    
  
    How many dimensions do we need?
    
  
    The right number is a trade-off between accuracy and speed, so we measure precision@4 for each size.
    
  
    
  
    Where does the curve flatten out? 150 dimensions is at or past the flattening point: about 14× shorter than 2,048 with almost no loss in retrieval quality. The best value depends on the dataset and the feature extractor, so always measure it.

    Scaling up with Annoy, and conclusion
    
  
    How do we scale to millions of images?
    
  
    Brute force compares the query with every vector, so the cost grows linearly with the number of items and the number of dimensions. Writing it ourselves shows how simple it is:
    
  
    Code: BruteForce and timing
    
  
    Brute force, 2048-d: 25.501 ms per query
    Brute force, 150-d : 0.771 ms per query  (33.1x faster)
    
  
    PCA to 150 dimensions shrinks the data about 14 times and (here) speeds up brute force about 33 times, though overheads mean the gain is usually smaller in practice. At our size brute force takes well under a millisecond, so at this size an approximate index has little to offer. At 10 million vectors the same search is over 1,000 times more work: roughly a second per query on one CPU core. With 100 requests per second you would need many cores or machines.
    
  
    Approximate nearest neighbours
    
  
      
    
    • They do not guarantee the exact nearest neighbours; they usually return the right ones, or very close, much faster.
      • 
    
    • Most expose settings that trade correctness for speed, and you can measure quality against brute-force results.
      • 
    
    • Libraries: Faiss (Meta), Annoy (Spotify), ScaNN (Google). Managed services: Google Cloud Vector Search, Pinecone, Milvus.
      • 
  
    
  
    PCA + Annoy
    
  
    Annoy (Approximate Nearest Neighbors Oh Yeah) is a C++ library with Python bindings, released by Spotify and used in production for their music recommendations. It builds a forest of random-projection trees. A query walks down each tree to collect candidates, and the closest candidates are returned. More trees give better accuracy but a larger index and a slower build. We build with the vector length (150) and 40 trees, using the Euclidean metric so results compare with brute force.
    
  
    Code: install and build the index
    
  
    Adding items          : 0.39 s
    Building 40 trees      : 0.35 s
    
  
    Since the result is approximate, we measure recall@5: the share of the true 5 nearest neighbours (from brute force on the same vectors) that Annoy returns. We exclude the query itself from both lists; otherwise it would count as a free hit. For the query shown earlier, Annoy and brute force returned the same five neighbours: [1540, 1486, 1520, 1598, 1538].
